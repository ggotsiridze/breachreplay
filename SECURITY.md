# Security

## Purpose

BreachReplay is a **defensive** network-forensics and incident-visualization project. It reads packet captures offline and explains what they show. It does **not** perform scanning, exploitation, credential attacks, traffic injection or any attack-back activity, and it should not be extended to do so.

## Handling captures

- Packet captures can contain sensitive data: internal addresses, hostnames, account names, URLs and payload fragments.
- **Only upload captures you are authorized to analyze.**
- Uploaded captures are processed server-side in an isolated per-job workspace and **deleted when the analysis finishes** (`KEEP_WORKSPACES=true` keeps them for debugging, so do not use it with real data).
- Incidents are held in memory only (bounded, most recent first) and are lost on restart.
- Raw packet contents are never returned by the API. Evidence records contain protocol metadata and short summaries.
- Never commit captures or analysis output. The repository `.gitignore` blocks `*.pcap`, `*.pcapng`, `*.cap`, `uploads/`, `analysis-output/`, `data/` and `tmp/`, and `scripts/verify.sh` fails if any are tracked.

## Public demo

- The bundled demo uses **synthetic** traffic generated by `scripts/generate_demo_pcap.py`. It contains RFC1918 and RFC 5737 documentation addresses, `.example` hostnames, a fictional account with empty NTLM responses, and plain-text markers. It contains no malware, exploit payloads or real credentials.
- A public deployment should use **Showcase mode** (`docker-compose.showcase.yml`), which serves a sanitized, precomputed incident, disables uploads and runs no analyzers.
- `PUBLIC_MODE=true` masks internal IP addresses in API responses. Showcase exports are always sanitized.

## Untrusted-input controls

| Area | Control |
|---|---|
| Upload | extension allow-list; streamed size limit (`MAX_UPLOAD_MB`, also enforced by nginx); pcap/pcapng magic-byte, version and link-type checks |
| Filenames | used for display only; path separators, `..`, control characters and over-long names rejected; storage uses a generated name |
| Process execution | argument lists with `shell=False`; no user-controlled arguments; minimal environment; timeouts kill the whole process group |
| Analyzer API | accepts only a job id matching `^[a-f0-9]{32}$` that resolves inside the workspace root; symlinked captures refused |
| Extracted files | never executed or opened (Zeek file extraction is not enabled) |
| Containers | non-root users, read-only root filesystems, `cap_drop: ALL`, `no-new-privileges`; analyzers on an `internal` network with no outbound access |
| Web | CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`; API and analyzer ports bound to localhost or kept internal |

## Not provided

- Authentication or multi-tenant isolation. Run BreachReplay locally or behind your own access control.
- Protection against analyzer vulnerabilities beyond container isolation. Keep the Zeek and Suricata images up to date.

## Reporting a vulnerability

Please report security issues privately through GitHub's *Report a vulnerability* (Security Advisories) feature on this repository rather than opening a public issue.
